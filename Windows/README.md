# Melon Tools for Windows

Порт приложения на **Tauri 2** (Rust + WebView2). Версия **3.1.1**.

Готовый **установщик** (с выбором папки) и портативный **Windows x64** доступны в [последнем релизе](https://github.com/ivankuprin/MelonTools/releases/latest/download/MelonTools-3.1.1-win-x64-portable.exe) — или обновитесь прямо из приложения: сайдбар → **«Обновить»**.
Скачайте и запустите `.exe`; это приложение, не установщик. Для запуска нужен
**WebView2 Runtime**. Файл не подписан Authenticode, поэтому Windows может
показать предупреждение. SHA-256 опубликован рядом с файлом; в PowerShell
проверьте его командой:

```powershell
Get-FileHash .\MelonTools-3.1.1-win-x64-portable.exe -Algorithm SHA256
```

Исходники и инструкции по сборке приведены ниже.

## Что умеет эта сборка

- **Шлюз (API Service)**: запуск/остановка/перезапуск локального OpenAI-совместимого
  шлюза на `http://127.0.0.1:18317/v1`, ключ доступа, сквозная проверка (маленький
  запрос через пул), живой счётчик «Запросов/мин» из журнала.
- **Аккаунты (пул ChatGPT)**: карточки с квотами 5 ч / неделя (полоса + процент +
  обратный отсчёт сброса), пауза по резерву (например, 5%), переключатель
  «Сделать текущим» — пишет `%USERPROFILE%\.codex\auth.json` в **полном формате**
  (`auth_mode` + `tokens.account_id` — фикс из macOS 1.4.5), обновление логина и
  квоты, удаление.
- **Живая синхронизация с шлюзом**: пауза/разблокировка по квотам пишется в
  auth-файлы шлюза сразу после обновления квот (сигнатура доступности).
- **Подключения**: API-ключи OpenRouter, OpenCode, DeepInfra и Vercel AI Gateway;
  модели `openrouter/*`, `opencode/*`, `deepinfra/*` и `vercel/*` появляются после
  загрузки каталога и перезапуска шлюза. Карточка OpenRouter показывает баланс,
  расходы и остаток лимита ключа; DeepInfra — число моделей и расход сессии;
  Vercel — баланс команды, общий расход и число моделей.
- **Интерфейс как в macOS**: сайдбар-карточка, группы «Обзор / Планировщик /
  Codex / Приложение», bento-карточки, шрифт Segoe UI Variable, капсульные
  кнопки и переключатели. Окно использует нативную рамку Windows с кнопками
  свернуть/развернуть/закрыть справа.
- **Запуск Codex**: кнопка **«Запустить Codex»** на странице API поднимает
  сервис, применяет маршрут и открывает приложение Codex. Если `ChatGPT.exe`
  не найден, открывается понятное окно с выбором файла, загрузкой Codex или
  повтором. Путь сохраняется в `settings.json` (`codexExePath`);
  `MELON_CODEX_EXE` остаётся скрытым запасным вариантом.
- **Сеть / Прокси**: включение прокси для OpenAI и провайдеров, URL прокси и
  список исключений. Пустой URL использует системный прокси Windows; локальный
  шлюз всегда работает напрямую.
- **Импорт JSON**: кнопка **«Импорт JSON»** на странице «Аккаунты» принимает
  Cockpit/CPA и sub2api-экспорт и сохраняет refresh-токены.
- **Планировщик**: задачи по расписанию (название, запрос, модель шлюза,
  опциональный reasoning effort, интервал или cron-выражение с часовым поясом).
  Пять шаблонов — утренняя сводка, проверка PR, недельная сводка репозитория,
  проверка логов и отчёт о расходе; переменные `{{repo}}`, `{{branch}}`,
  `{{path}}` подставляются при сохранении. Задачи выполняются, пока Melon Tools
  работает в трее (закрытие окна не останавливает процесс); тик — 30 секунд,
  одна задача за раз. «Выполнить сейчас» запускает задачу вне расписания и
  сдвигает следующий запуск. Результаты и ошибки хранятся в истории: до 20
  записей на задачу и 200 всего, текст результата — до 64 КиБ.
- **Настройки**: внешний вид, язык RU/EN, акцент, виджеты обзора, порт шлюза,
  интервал автообновления квот, уведомления, сеть/прокси, резервная копия и
  автозапуск.
- **Донат**: USDT (TRC20) с копированием адреса.

## Где лежат данные

```
%APPDATA%\MelonTools\
├── codex\accounts.json     ← vault аккаунтов (формат совместим с macOS-версией)
├── settings.json           ← настройки
├── scheduler.json          ← задачи планировщика и история запусков
└── gateway\
    ├── config.yaml         ← конфиг CLIProxyAPI
    ├── auths\*.json        ← аккаунты для шлюза (пауза = "disabled": true)
    └── gateway.log         ← журнал шлюза
```

Vault можно перенести с macOS: скопируйте
`~/Library/Application Support/MelonTools/codex/accounts.json`
в `%APPDATA%\MelonTools\codex\accounts.json` — аккаунты и подписки подхватятся.

## Интеграция с Codex

- **Route Codex** — приложение пишет `%USERPROFILE%\.codex\config.toml`
  (`model_provider = "melon_local_access"` + провайдер с bearer-токеном),
  так что Codex ходит через локальный шлюз. Настраивается автоматически при
  запуске шлюза и кнопкой на странице API; снимается кнопкой там же. Бэкап
  исходного файла: `config.toml.melon-backup`.
- **Каталог моделей** — `melon-model-catalog.json` собирается из базового
  каталога + живого списка моделей шлюза (модели `opencode/*` и
  `openrouter/*` добавляются в пикер сгруппированно).
- **Чипы в композере** — мост подключается к Codex через DevTools-протокол
  (как на macOS): аккаунты, квоты 5ч/неделя, запросы/мин. Для работы Codex
  должен быть запущен с debug-портом — кнопка **«Перезапустить Codex с
  чипами»** на странице API делает это автоматически. Состояние моста
  (подключён/нет и причина) видно в карточке «Интеграция с Codex».

## Текущие ограничения Windows-приложения

- **Оценка стоимости**: сумма в чипах и карточках рассчитывается по токенам и
  тарифу выбранной модели; если тариф неизвестен, цена не показывается.
- **Метрики в чипах**: доступны данные OpenRouter, DeepInfra и Vercel; OpenCode
  не предоставляет совместимый endpoint для таких метрик.

## Сборка

Для установщика нужен NSIS: `brew install makensis`.

## Кросс-сборка из macOS или сборка на Windows

Исходники: `app/` (`ui/` — фронтенд без сборки, `src-tauri/` — Rust).

На macOS для кросс-сборки (см. `build-windows.sh`):

```bash
rustup target add x86_64-pc-windows-msvc
cargo install cargo-xwin --locked
brew install lld llvm
./build-windows.sh
```

На Windows установите Rust (toolchain из CI), затем соберите exe и установщик
штатными шагами:

```powershell
cd Windows/app/src-tauri
cargo build --release --locked
cd ../..
makensis /DVERSION=3.1.1 /DSOURCE_EXE=..\dist\MelonTools-3.1.1-win-x64-portable.exe installer\MelonTools.nsi
```

`cargo tauri build` **не используется**: установщик — рукописный NSIS-сценарий
`installer/MelonTools.nsi`, который вызывает `makensis` после `cargo build
--release`. CI делает то же самое (`.github/workflows/release.yml`). Сборка
использует включённый в репозиторий сжатый движок шлюза.

## Технические детали

- Окно: нативная рамка Windows с кнопками свернуть/развернуть/закрыть справа,
  тёмная тема. Кнопка закрытия скрывает приложение в трей.
- Движок: CLIProxyAPI (Go), собран под `windows/amd64`, конфиг 1:1 с macOS-версией
  (`fill-first`, retry 3, disabled-флаг для пауз). Движок **встроен в exe** в
  сжатом виде (zlib, ~24.2 МБ; ~74.5 МБ после распаковки) и распаковывается в `%APPDATA%\MelonTools\engine\`
  при первом запуске или после обновления версии. Blob воспроизводится из
  пина `1f917e77c4562623aa49e9804d999524151a2f96` (`v8.0.44`, Go 1.26.10)
  скриптом `Windows/scripts/build-engine.sh`; CI сверяет SHA-256 с
  `Windows/app/resources/engine-provenance.json`.
- Фронтенд: ванильный HTML/CSS/JS, дизайн-токены перенесены из `MTTheme.swift`
  (палитра, отступы, карточки, золото).
- Сеть: reqwest (native-tls → schannel на Windows), без OpenSSL.
- Чипы: CDP через WebSocket (`tokio-tungstenite`), базовая версия
  `composer-chips.js`; расширенные данные Claude/Antigravity пока есть только
  в macOS-версии.
