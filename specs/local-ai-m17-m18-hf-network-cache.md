# SPEC — M17/M18: ошибки Hub, повторы, таймауты, кэш аватаров

Источник требований: `specs/local-ai-audit-remediation-2026-11-07.md` (M17, M18) и
`AUDIT-LOCAL-AI-2026-11-07.md` §4.2.3. Режим: SpecLoop, запись — этот файл.
Область: `MacOS/app/MelonTools/LocalAI/HuggingFaceService.swift`,
`MacOS/app/MelonTools/LocalAI/HFAvatarService.swift`.
`Core/NetworkProxy.swift` — только при необходимости таймаутов; сигнатура
`directSession()` неизменна.

## Текущее поведение (проблема)

- `HuggingFaceService`: любая не-2xx превращается в `NSError` с одним текстом
  «status code N»; тело ответа, URL и HTTP-статус не сохраняются, повторов нет,
  явного таймаута нет (наследуется 60 c запроса / 7 дней ресурса у `URLSession`).
- `HFAvatarService`: `requests[key]` создаётся и никогда не удаляется; кэш на диске
  растёт без границы (200 записей не предел); `store(nil)` пишется на 7 дней и для
  `429`/`5xx`/сетевой ошибки, поэтому «битый» ответ скрывает аватар на неделю.

## Желаемое поведение

M17:
1. Все HTTP-отказы Hub → `NSError` (domain `HuggingFaceService`, `code == status`) с
   `NSLocalizedDescriptionKey`, включающим статус и тело не длиннее 512 символов,
   `NSURLErrorKey` = URL запроса, `"HTTPStatus"` = статус.
2. Таймаут запроса задан явно: `URLRequest.timeoutInterval = 30`.
3. `429` и `5xx` → ровно один повтор через 1 с (максимум 2 попытки, без циклов).
4. Успешный путь и разбор JSON не меняются; `fetchReadme` по-прежнему отдаёт `""`
   на `404`.

M18:
5. `requests[key]` удаляется в `defer` после ожидания задачи.
6. Кэш ограничен 200 записями, вытеснение LRU по `lastUsed`; поле `lastUsed: Date?`
   опционально (старый `hf-avatars.json` без него читается), дефолт — `at`.
7. `store(nil)` только когда Hub окончательно ответил `404` (оба эндпоинта);
   `429`/`5xx`/сетевая ошибка не кэшируются.
8. Запись JSON остаётся `.atomic`; за счёт границы в 200 записей файл ограничен.
   На каждое попадание в кэш диск не пишется: `lastUsed` обновляется в памяти и
   сохраняется следующей записью.

## Допущения и решения

- Используется существующая сессия `NetworkProxy.session()` (прокси-осведомлённая,
  общая для внешнего трафика). Своя `URLSessionConfiguration` не создаётся: менять
  общую сессию приложения (обновления, провайдеры, стриминг) ради двух запросов Hub
  нельзя, а `directSession()` отключил бы прокси для huggingface.co. Поэтому
  таймаут задаётся на `URLRequest` (30 с) — по условию задачи это допустимая
  альтернатива; `timeoutIntervalForResource` остаётся настройкой чужой сессии и в
  отчёте отмечен как ограничение.
- «Окончательное отсутствие аватара» = оба эндпоинта (`organizations`, `users`)
  ответили `404`. Ответ `200` без валидного `avatarUrl` считается неокончательным и
  не кэшируется: лишний запрос дешевле скрывшегося аватара.
- Отмена: `Task.sleep` между попытками пробрасывает `CancellationError`, повтор
  после отмены не выполняется.

## REVIEW

Независимый ревьюер недоступен: глубина делегирования в сессии исчерпана (0 уровней),
поэтому REVIEW выполнен как самопроверка по диффу и прогону harness.

Что проверено вручную:

- Единственный сырой вызов сети в `HuggingFaceService.swift` — внутри `send(_:)`
  (`NetworkProxy.session().data(for:)`); три публичных метода идут через `reply(for:)`.
  Обрезка тела — `data.prefix(512)`, до декодирования в строку, поэтому многобайтовые
  символы не рвут описание в нечитаемое.
- Повтор только для `429`/`5xx` и только один; `Task.sleep` отменяем, поэтому отмена
  вью не превращается в лишний запрос.
- `store(_:for:)` при `.failed` выходит до записи на диск, поэтому сетевой сбой не
  «залипает» на 7 дней; `.absent` пишется только при двух `404` и отсутствии
  неопределённых ответов.
- `evictOldest` исключает только что записанного издателя из жертв, поэтому новая
  запись не вытесняет сама себя при `count == maximumEntries + 1`.
- `defer` в `avatarURL` снимает слот и при отмене вызывающего: `Task<URL?, Never>.value`
  не бросает, поэтому `defer` выполняется всегда.
- Совместимость: `lastUsed` — `Date?`, старый файл декодируется; битый файл даёт `[:]`
  и просто перезаписывается.

Замечания и сознательные отклонения (для интегратора):

1. `timeoutIntervalForResource = 120` не выставлен: единственный общий `URLSession`
   приходит из `NetworkProxy.session()` (кэшируется по сигнатуре прокси) и используется
   ещё апдейтами, провайдерами и стримингом; создание своей сессии отключило бы прокси,
   а изменение сигнатуры `directSession()` запрещено. По условию задачи выбран
   разрешённый вариант — таймаут на `URLRequest` (30 с).
2. Запросы аватарок не повторяются: требование о повторе в M18 не заявлено, а `404`
   должен оставаться дешёвым. После `429`/`5xx` аватар просто не кэшируется.
3. Текст ошибок унифицирован («Hugging Face returned status code N: …») вместо прежних
   разрозненных формулировок; ни тесты, ни UI не сравнивают строки (проверено grep'ом
   по `MelonToolsTests` и вью).
4. Файл кэша, записанный до этого изменения и уже превышающий 200 записей, ужмётся при
   первой новой записи (`.failed` не пишет, поэтому чисто-читающая сессия его не
   уменьшит); сверх лимита он при этом не растёт.
5. `lastUsed` при попадании в кэш обновляется только в памяти (без записи на диск на
   каждый аватар); порядок LRU между запусками определяется последней реальной записью.
