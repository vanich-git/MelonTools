# Windows: каталог Local AI и виджет при открытии «Пуска»

## SPEC
- Базовая ревизия: b8556ffb4b6e954079d65b37d7c5a2b64fa07a18; существующие локальные изменения сохраняются.
- R1: реально загруженная модель появляется как `local/*` в `/v1/models` и доступна для маршрутизации; не объявлять успех на основании только ответа reload.
- R2: при ошибке публикации отображать доказанную причину, а не предположения; не скрывать сбои.
- R3: открытие и закрытие «Пуска» не должно приводить к заметному исчезновению или мерцанию виджета; сохранить остальную логику размещения и взаимодействие с окнами.
- R4: регрессионные тесты значимых путей; полный Rust test, Windows cross-build и локальная упаковка без установки и загрузки.
- R5: проверить фактический diff независимым ревьюером, проверка Windows в реальной ОС требуется для подтверждения пользовательского эффекта; при отсутствии ОС не заявлять сквозной PASS.
- R6: в Windows web UI использовать `-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`; в SwiftUI — нативный системный шрифт, в web-контенте тот же CSS-стек. Сохранять различимые размеры и начертания для иерархии, технический моноширинный текст — только там, где он действительно необходим.
- R7: поисковые компоненты отображаются одним полем без вложенной рамки и дублирующего native clear; клавиатура, видимый фокус, ввод и очистка не ломаются.
- Область: необходимые части Windows gateway/Local AI, виджета, типографики macOS/Windows, поисковых компонентов и тестов; ранее существующие изменения не откатывать. Артефакты — внутри репозитория на внешнем диске. Никаких commit, push, установки или обновления приложений.

## EVIDENCE
- Новые изображения: Local AI работает, модель Qwen3.5 2B BF16 загружена, каталог шлюза содержит 15 моделей, но 0 локальных. Сообщение сообщает об отсутствии local alias после переписываний конфигурации.
- Предыдущий диагноз о timeout не подтверждён и не объясняет новые данные; текст о том, что provider был отброшен, сам по себе не доказывает причину.
- Исследование исходников движка v8.0.44: старый PUT `/v0/management/config.yaml` валидирует и сохраняет файл, но не инициирует напрямую обновление in-memory клиентов; оно зависит от watcher. Маршрут `/v8/management/config.yaml` запускает отдельный reload hook, но его ответ асинхронен и сам по себе не подтверждает публикацию в каталоге. Обнаружен также потенциальный race между снимками expected и генерацией конфигурации; факт срабатывания этой гонки у пользователя пока не подтверждён.
- На момент начала хеши commands.rs: 1f60fbba93ba2d8ab0cc8c7311a316aae0058ca4b367de4d5ecef9c2db4ed27d; taskbar_widget.rs: e80205662bfd2e62319a79a0cff70bab6c96095aef9959ffc7ffc34b5a15e410.
- Проверки: cargo test --offline с внешним CARGO_TARGET_DIR; cargo xwin build и Windows/build-windows.sh; проверка хешей доставленных файлов. Реальная Windows для интерактивной проверки пока отсутствует.

- macOS: `xcodebuild ... test` — 473 tests, 7 skipped, 0 failures, `TEST SUCCEEDED`; предупреждение xcodebuild о сборе logarchive не повлияло на результат тестов. Обновление CSS встроенного web и OAuth прошло синхронизацию ресурсов.
- Windows типографика/поиски: реализована общая разметка для четырёх форм, сброшена рамка вложенного input, заданы focus-visible и единый шрифт. Разработчик сообщил об успешных статических и Chromium проверках. Независимое ревью ожидается.

Точный механизм мерцания и фактическое поведение Start остаются неподтверждёнными без Windows. Независимое ревью ожидается.

На внешний exFAT нельзя надёжно перенести неподписанный bundle с метаданными: образ сформирован из подписанного локального staging, без установки.

## REVIEW
- Изолированное ревью типографики обнаружило невидимый idle-search в светлой теме, нефокусируемые иконку/паддинг, ложное обещание Escape у pool и отсутствие полноценной модальной навигации. Исправления подтверждены повторным независимым Chromium-ревью и постоянным тестом search-fields-check; замечания об интерактивном button внутри label и двойной фокусной обводке исправлены и повторно независимо проверены. Тест пока не подключён в CI.
- Изолированное ревью виджета обнаружило, что прежний код уже распознавал распространённый Start CoreWindow, а ветви ошибок геометрии до классификации оболочки по-прежнему скрывают виджет; новых тестов для этого недостаточно. Причина реального мерцания не доказана. Передано на переработку с grace-периодом и тестами состояний.
- Независимое ревью gateway выявило потерю настройки stream bootstrap timeout, некорректную трактовку асинхронного HTTP 200 как применения, возможную перезапись новых настроек старым снимком, невидимые ошибки при пустом каталоге и риск управления ban из-за повторных 401. Разработчик сообщил об исправлениях; повторное ревью продолжается. Созданные до ревью артефакты предварительные: после изменения engine patch их необходимо пересобрать на обеих платформах.

## LOOP
Выполнено не менее 16 отдельных итераций REPAIR: gateway — 11, виджет — 3, поиск — 2; в счёт gateway включены последующие правки атомарности, повторной публикации, доступности и состояния авторизации после REPAIR 7. Дополнительная попытка scoped settings не прошла ревью и безопасно откачена, она не считается исправлением. Ревьюеры были отдельными агентами и не редактировали проверяемые изменения.

Повторное ревью виджета подтвердило адресные исправления REPAIR 3; исходная причина и фактическое поведение на Windows остаются неподтверждёнными. Известные риски включают распознавание shell, неограниченное удержание позиции при открытой shell-поверхности, DPI и polling. Поиск после REPAIR 2 независимо проверен в Chromium с mock API, не в WebView2.

Повторные независимые ревью gateway подтвердили forced restore, атомарность проверки локального поколения и отметки публикации, обработку поздних auth-результатов и резервирования probe. Локальная запись нового поколения инициирует повторную публикацию при доступном порту; TCP-проверка не доказывает идентичность процесса. Строгая привязка PID к проверенному порту и защита от TOCTOU в adopt остаются неполными. Внешние писатели конфигурации не учитываются process-local счётчиком. Устаревший payload формы настроек может перезаписать более новое значение: попытка scoped-решения откачена после ревью. Одинаковый digest не доказывает завершение конкретного повторного поколения. Риски не объявляются исправленными.

Текущий снимок: Rust `cargo test --locked --bin melontools` 486 passed, 1 ignored; Windows cross-check с тестовыми целями и release build успешны; проверка embedded engine и воспроизводимости прошла. macOS DMG, Windows portable и NSIS setup собраны локально в `MelonTools-local-2026-11-07`, SHA256SUMS проверен. macOS Release ad-hoc signed, не notarized. Windows приложения и установщик не запускались. Интерактивная проверка R1/R3/R5 на реальной Windows недоступна, поэтому общий результат SPECLOOP BLOCKED, а не PASS.
