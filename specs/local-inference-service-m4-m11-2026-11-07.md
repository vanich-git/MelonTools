## SPEC

### M4. Мёртвый `gatewayYAML()`
- Удалить метод и ставший лишним `// MARK: - Gateway Integration`; проверить, что
  приватных помощников, использовавшихся только им, нет.
- Критерий: `grep -rn gatewayYAML` не находит метод сервиса; сборка не ссылается
  на удалённое; YAML для шлюза по-прежнему формирует `ModelSourcesStore` /
  `ModelCatalogOverlay`.

### M7. Process group и поколения
- После `p.run()` вызвать `setpgid(p.pid, p.pid)`; `EACCES` допустим, если группа
  уже совпадает с pid. Предупреждать только при реально отсутствующей группе.
- `SIGTERM`/`SIGKILL` посылать всей группе (`kill(-pid, …)`) с откатом на
  `kill(pid, …)` только при `ESRCH`/`EPERM`.
- `terminateProcess(expectedGeneration:)` не посылает сигналы, если процесс уже
  заменён другим поколением. `stop()` и `stopWithoutBumpingGeneration()` сверяют
  поколение после каждого `await` и не публикуют состояние, если их обогнали.
- `stopWithoutBumpingGeneration` не должен ломать restart: процесс, которым он
  владеет, всё равно добивается; чужой новый процесс не трогается.
- Критерий: остановка во время `p.run()` не оставляет живой router; stale Stop не
  убивает engine нового Start.

### M8. Reaper не убивает чужие процессы
- Заменить `pgrep -f` + безусловный `kill` на разбор
  `ps -axo pid=,ppid=,command=`.
- Убивать только router'ы с нашим binary path, `--host 127.0.0.1` и портом из
  `18318...18348`, если они осиротели (`ppid == 1`) или их родитель уже мёртв;
  плюс их model-детей и осиротевших model-детей с путём `LocalPaths.models`.
- Процесс с живым родителем (в том числе нашим приложением) не трогать. При
  `RuntimeStore.shared.activeBinaryURL == nil` — no-op.
- Критерий: fixture с чужим процессом, упоминающим тот же бинарник, не попадает в
  список; реальный `ps` разбирается; пустой binary → пустой список.

### M9. `stopSync()` без 3-секундного busy-wait
- `SIGTERM` группе, не более 10 × 50 мс; при необходимости `SIGKILL` и не более
  4 × 50 мс. Суммарное ожидание процесса ≤ 0,7 с.
- Reaper на пути выхода запускать только если группа пережила TERM или был
  SIGKILL; он ограничен (~0,2 с), чтобы общий худший случай оставался меньше 1 с.
- Критерий: нет `usleep`-цикла на 3 с; чистый выход не ждёт reaper.

### M10. `checkHealth` требует статус
- `true` только при HTTP 200 и JSON `status` равном `ok` или `ready`; пустое тело,
  `null`, иной статус, не-JSON, не-200 → `false`.
- Критерий: локальный сервер с `/ok`, `/ready`, `/empty`, `/null`, `/loading`,
  `/invalid`, `/bad` даёт `true,true,false,false,false,false,false`.

### M11. `routerStatesSnapshot` различает ошибку и пустоту
- Возвращать `[String: RouterModelStatus]?`; `nil` при ошибке запроса, не-200 или
  неразборчивом теле; `[:]` — валидный пустой ответ.
- Все вызывающие: при `nil` не менять статусы, только логировать; пустой словарь
  по-прежнему нормализует transient-состояния.
- Критерий: `200` с `data` → статусы, `200` с пустым `data` → `[:]`,
  `500`/мусор → `nil`.

## REVIEW

- M4: удалён только мёртвый метод; MARK переименован в `Errors`, чтобы
  `errorMessage` не висел под чужим разделом. Публичный API не менялся.
- M7: поколение процесса захватывается до `generation += 1`, иначе Stop считал бы
  своим уже новый процесс. После `await` поколение проверяется повторно; stale
  ветка всё же добивает процесс, который сама запустила, и не трогает чужой.
  `setpgid` не считается ошибкой при `EACCES`, если `getpgid(pid) == pid`.
- M8: принадлежность доказывается совокупностью binary + loopback + порт из
  диапазона + отсутствие живого родителя. Это исключает `pgrep`-совпадения по
  одному пути. Дети router'а добиваются вместе с группой, а оставшиеся — reaper'ом.
- M9: главный поток больше не спит 3 с; верхняя граница ожидания процесса 0,7 с,
  reaper условный и ограничен ~0,2 с. `stopSync` по-прежнему синхронный, потому что вызывается из
  `applicationWillTerminate`.
- M10: проверка тела закрывает подмену движка чужим локальным сервисом. В
  `docs/RSS_ROUTER_B12099.md` контракт тела `/health` не описан — это пробел
  документации, не кода.
- M11: `nil` и `[:]` теперь разные ответы; монитор при `nil` сохраняет последние
  статусы, при пустом успешном ответе нормализует transient. В ветке старта
  текущая модель помечается `.loaded` только после подтверждённого `/models/load`,
  это не догадка из пустого снапшота.
- Риск: жёсткий диапазон портов 18318...18348 продублирован в reaper; при смене
  диапазона в `findAvailablePort` его нужно менять и там. Вынесение константы
  затронуло бы существующий код вне находок.
