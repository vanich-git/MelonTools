# Hugging Face — интеграция

## Источник

Официальный Hub API: `https://huggingface.co/api`.

## Поиск

`GET /api/models?filter=gguf&sort=<order>&direction=-1&limit=<n>&offset=<n>`

- Поиск по названию и автору через параметр `search`.
- Сортировка: downloads, likes, last modified, trending.
- Пагинация: кнопка «Загрузить ещё» запрашивает следующую страницу; весь каталог
  в память не загружается.
- Вставка ссылки: `https://huggingface.co/owner/repo`, `owner/repo` и ссылки с
  хвостом `/tree/main/...` открывают карточку сразу, без поиска.

## Карточка

Показываются только полученные поля: автор, описание, загрузки, лайки, дата
обновления, лицензия, признак закрытого доступа, список GGUF-файлов с размерами и
оценкой памяти. Отсутствующие значения скрываются, а не подставляются.

## Размеры файлов

Запрос деталей выполняется с `?blobs=true`. Размер берётся из `lfs.size`, при его
отсутствии — из `size`. Без `blobs=true` LFS-файлы приходят без размера, что
ломает прогресс и показывает «0 KB».

## Целостность

Для LFS-файлов Hub публикует `lfs.sha256`. После скачивания приложение считает
SHA-256 потоково и сравнивает. При несовпадении файл удаляется, загрузка
помечается ошибкой. Если дайджест не опубликован, файл проверяется только
структурно (magic GGUF и размер) — приложение не утверждает, что он проверен.

## Возобновление

Ответ `206 Partial Content` даёт реальный размер в `Content-Range`. При
возобновлении отправляется `If-Range` с сохранённым `ETag`/`Last-Modified`:
если файл на стороне Hub изменился, сервер вернёт `200` и загрузка начнётся
заново вместо склейки двух разных ревизий.

## Токен

Необязателен, но повышает лимиты и открывает закрытые модели.

| Платформа | Хранилище |
|---|---|
| macOS | Keychain, `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` |
| Windows | DPAPI, шифротекст в `metadata/hf_token.bin` |

Токен не попадает в `localStorage`, логи и конфигурацию шлюза. Интерфейс знает
только, сохранён ли токен.
